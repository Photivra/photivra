# Changelog

## 2.0.0 — unreleased (prepared October 17, 2026)

A major release. It contains the correctness fixes and bit-identical performance work of the first 2.0 review (#270–#288) and the 2.0 feature streams (#290–#304): sensor gain and fixed-pattern noise, colorimetry, RAW development fixes, optics, rolling shutter and flash, export formats, image processing, the `simulateCapture()` facade and an opt-in WebGPU backend. Several changes alter numerical output, change serialized identities or reject input that 1.x accepted, so the root package takes a major version. Root exports grow from 1,227 to 1,627 symbols, and none is removed. See [the 2.0.0 release record](https://github.com/Photivra/photivra/blob/main/docs/RELEASE_2_0_0.md) for the science evidence and the compatibility table.

### Breaking changes

Each item ends with its migration. Several items only widen a type union; they break only code that switches exhaustively over that type.

**Sensor and noise**

- **Noise model `photivra-native-raw-noise` 0.4.0, with independent per-site seeds (#270, #283, #290).** Per-site charge and read-noise seeds are now `MurmurHash3_x86_32(captureSeed, absoluteNativeIndex, streamId)` (seed schedule `murmur3-capture-seed-native-index-stream-v2`), and `createRandom` scrambles its seed with the MurmurHash3 `fmix32` finalizer. The old `seed + 2i` schedule gave neighbouring pixels a lag-1 correlation of about 0.84. Every realized RAW code and every recorded seed changes, including direct `simulateSensorChargeRealization`/`simulateSensorRawCode` calls. Result model versions: charge realization **3.0.0**, stochastic RAW code **4.0.0**, expected readout **2.0.0**. *Migration:* results stay deterministic for a given seed at any tile width, but 1.x realizations cannot be reproduced. Captures, plans and replays that carry noise model 0.1.0–0.3.0 are rejected; re-capture with 2.0.0 and keep old outputs as historical artifacts.
- **ISO now drives sensor gain; generic tier presets 2.0.0 (#290).** Readout regimes `base`/`high` are replaced by per-ISO regimes `iso-<S>` with 12-bit (consumer) or 14-bit ADCs, and `presetVersion: "1.0.0"` is rejected. The producer rejects a regime whose `exposureIndexGain.exposureIndex` differs from `capture.exposure.iso`. New required result fields: `SensorChargeRealization` gains `fixedPatternNoiseProfileId`, `photoResponseGainFactor`, `darkCurrentFactor`, `hotPixel`, `photoSampledMeanElectronCount` and `darkSampledMeanElectronCount`; `SensorRawCodeSample` gains `fixedPatternNoiseProfileId`, `fixedPatternReadoutOffsetElectrons`, `adcIntegralNonLinearityOffsetCodes`, `adcCodeBeforeDigitalGain` and `digitalGain`; `SensorExpectedReadoutSignal` gains `adcIntegralNonLinearityOffsetCodes`, `digitalGain` and `expectedCodeAfterDigitalGain`, and `expectedDigitalSaturation` now uses the post-digital-gain code. *Migration:* save selections and optical states with preset 2.0.0 and pick the `iso-<S>` regime that matches the capture ISO.
- **Capacity assessments are bound to their charge (#273, #280).** An assessment must match the charge it is applied to, by exact equality of `totalExpectedStoredElectronCount`, on both readout paths. The stochastic path reports `digitalSaturationApplied` once the code reaches (`>=`) the digital saturation code. *Migration:* compute the assessment from the same charge you pass.

**RAW development and DNG**

- **RAW development output changes (#295).** White balance is no longer applied twice with non-white-normalized camera matrices; normalization uses the effective white rather than digital full scale; clipped highlights stay neutral and saturation flags are honoured. DNG output changes: WhiteLevel, AsShotNeutral, BlackLevel/CFAPattern phase (now relative to the ActiveArea origin) and DNGVersion (now 1.4). `simulationHash` and file hashes change. `diagnostics.captureSaturation` can be `"consumed-in-raw-development"`. *Migration:* re-develop and re-export; update stored hashes.
- **New required RAW fields (#295).** `NativeRawOutput` requires `effectiveSaturationCodes` (one Uint16 per CFA phase). `SensorRawCaptureSample` requires `effectiveSaturationCode`, `systemConversionGainElectronsPerCode` and `readNoiseRmsElectrons`, each constant per CFA phase. *Migration:* hand-built RAW objects must supply them; `calculateEffectiveSaturationCode` computes the first.
- **`createNativeRawDevelopmentTask` takes ownership of `input.raw` (#295).** Its arrays are detached (zero-copy `ArrayBuffer.transfer`, or copied where unsupported) and returned in `output.raw`. RAW integrity errors (spans, flags, white levels) now surface from `run()` rather than at creation. The provider is now `{ yieldControl, onProgress? }`; a bare function is deprecated but still accepted in 2.x. *Migration:* copy the RAW first if you still need it, and handle integrity errors from `run()`.

**Optics and geometry**

- **Exact thin-lens depth-of-field limits (#271, #279, #293).** `calculateDepthOfField` (and `simulatePocCamera().depthOfField`) uses near = s(H − f)/(H + s − 2f) and far = s(H − f)/(H − s), infinite (`null`) when s ≥ H; model `thin-lens-depth-of-field` 1.1.0. For 50 mm f/8, c 0.03 mm, s 5 m the limits move from 3.394595/9.486405 m to 3.389371/9.527439 m. It now rejects `circleOfConfusionMm ≥ focalLengthMm/aperture`. `calculateDefocusCircle` uses a stable closed form (model 1.1.0); values change in the last bits, more where cancellation used to occur. *Migration:* update stored expectations; there is no option for the old approximation.
- **Camera rotation sign on all three axes, and shake pitch sign (#276, #284).** Rotation mappings now follow the documented right-hand rule about camera +X/+Y/+Z; 1.x produced the mirror image on every axis. Positive yaw gives `deltaMm.x = +d·tan(yaw·t)`, positive pitch gives `deltaMm.y = −d·tan(pitch·t)`, and positive roll rotates content counter-clockwise. Everything built on the mappings changes with them (trajectories, temporal quadrature, rolling-shutter paths, aperture rays, environment radiance query and capture). `estimateCameraShakeBlur()` keeps its yaw sign, but its pitch `deltaYmm`/`deltaYPixels` flip sign, and it rejects a per-axis rotation ≥ π/2 over the exposure. Rotation and stabilization provenance models go to 2.0.0. *Migration:* negate all three angular-velocity components to reproduce 1.x mappings; negate the pitch rate to reproduce 1.x shake values.
- **Complex-pupil PSF zero padding and support bound (#276, #284, #293).** `calculateLensComplexPupilPsf()` pads each axis to M = max(grid, 2S − 1), the exact no-wrap condition (Goodman sampling Q > 2). Pupils whose support exceeds (grid + 1)/2 samples get a larger kernel with different values (a full 5×5 disk becomes 9×9). Support wider than `propagationDistanceMm / apertureFNumber` throws `InvalidScientificInputError`; `sampling.declaredPupilDiameterMm` reports that bound. Model 2.0.0; tier envelopes re-baselined. *Migration:* read kernel geometry from the returned kernel and fix profiles whose support contradicts their f-number.
- **Crop rounding; crop models 2.0.0 (#276, #282, #293).** `calculateCenteredCrop` floors the shorter axis and derives the longer one as round(short · L / S), capped at floor(L / cropFactor); a quotient within 4 ulps of the next whole pixel counts as that pixel. The longer axis can be 1 px smaller than in 1.x (6000×4000 at 1.7× gives 3528×2352). `calculateSubjectFramingCrop` no longer reports a fitting subject as clipped. *Migration:* update stored crop dimensions.
- **35 mm crop factor (#293).** The crop factor is now √(1872/(w² + h²)) and the diagonal avoids `Math.hypot`, so some `cropFactor35Mm`, `diagonalMm` and `equivalentFocalLength35Mm` values change by 1 ulp. *Migration:* none for archives; stored focal equivalents are accepted within 8 ulps.
- **Type widenings (#296, #303).** `LensSampledPsfProfile.interpolation` is the union `LensSampledPsfInterpolation`. Front-of-lens filter `polarizationModeled` fields are `boolean`, filter `schemaVersion` is `"0.1.0" | "0.2.0"`, `compositionModel` gains a Stokes–Mueller value, and results add `incidentPolarization`/`transmittedPolarization`. `PreparedGeometricMapping.schemaVersion` is `"0.1.0" | "0.2.0"`, the transform purpose union gains `"projection"`, `DigitalGeometricTransform` gains two variants, `SensorEnvironmentRadianceQuery.projection` can be `null` (only with a non-rectilinear mapping), and `ProductionImageFormationBlockerCode` gains `missing-lens-field-mapping`. *Migration:* existing 0.1.0 profiles and documents work unchanged; update exhaustive switches.

**Exposure, motion and flash**

- **Flash, readout and metering unions (#297).** `FlashSyncCapabilityProfile.highSpeedSyncSupported` is `boolean` with optional `highSpeedSync`, and `schemaVersion` is `"0.1.0" | "0.2.0"` (0.1.0 documents parse unchanged and cannot claim HSS). `ProductionTemporalCaptureResult.readoutExposureSynchronization` adds `"electronic-rolling-shutter-line-linked"`. `CreateManualFlashIlluminationOverlayInput.resolvedSync` widens to `FlashOverlaySyncRegistration`. `ExposureMeteringPolicy` gains `highlight-priority`. Metering provenance `relative-pre-exposure-metering` is 1.1.0 with no value change. *Migration:* update exhaustive switches; use a 0.2.0 sync profile for HSS.
- **White-balance source `"color-temperature"` (#291).** `ResolvedWhiteBalanceState.source` and `CaptureWhiteBalanceIntent.source` gain this value; the `adopted-white-xyz-scaling` variant of `CaptureColorWhiteBalance` gains an optional `transform`, rejected on other kinds. *Migration:* add a case to exhaustive switches; existing serialized states still parse.

**Serialization, validation and export**

- **Stricter input validation (#276, #282, #293).** Canonical JSON rejects non-plain objects (Map, Set, Date, typed arrays, class instances and similar) and array holes instead of hashing them as `{}`; output for plain JSON is byte-identical. Root functions throw `InvalidConfigurationError` for null, primitive, array or missing sub-object input, and the 15 scalar calculators reject unknown fields. `estimatedResult`/`calibratedResult` require `quality`, and result factories reject empty provenance identities. `calculateSensorResponsivityPhotocurrent` always validates `operatingElectricalConditions` and returns them parsed. `serializeProductionImageFormationPlan` rejects objects whose version or fingerprint does not match. *Migration:* pass plain JSON, remove extra fields and give factories a quality and provenance.
- **Spectral channel binding format v2 (#276, #282, #293).** `SENSOR_SPECTRAL_RESPONSE_CHANNEL_BINDING_FORMAT` is `photivra-spectral-channel-response-canonical-json-v2` (sorted-key JSON of the parsed channel). v1 bindings from 1.5.0 and earlier are rejected with a version error. *Migration:* recompute the quadrature and reduction with 2.0.0.
- **Print JPEG schema 0.2.0 and baseline JPEG encoder v2 (#274, #278, #298).** Print JPEG output gains `encoderId`; IFD0 always carries XResolution/YResolution/ResolutionUnit (72 dpi when `pixelsPerInch` is omitted, the Exif 2.32 value for unknown resolution) and YCbCrPositioning; the Exif IFD adds ExifVersion `"0232"`, FlashpixVersion and ComponentsConfiguration. The paired-export JPEG gets the same tags. `EXPORT_JPEG_ENCODER_ID` is `photivra-baseline-jpeg-444-v2`: correctly rounded DCT cosines and half-away-from-zero quantization, so bytes differ from 1.x only where a coefficient sat within about one ulp of a half-integer, and are now identical across V8 and JavaScriptCore. `maximumProviderReads` now caps exactly ⌈crop height/32⌉ × ⌈crop width/256⌉ crop-aligned strip reads and fails before the first read when too small. *Migration:* treat JFIF units = 0 or the absence of `pixelsPerInch` in the XMP plan as "no physical size", and size the read budget by the new formula.
- **POC API 1.0.0 (#276, #282, #293).** `POC_SIMULATION_API_VERSION` is **1.0.0**; `simulatePocCamera()` values change through depth of field, crop and shake pitch. The repository-only POC transport (not a package export) returns 400 for out-of-envelope aperture/focus and malformed JSON (fixed message), 413 `PAYLOAD_TOO_LARGE`, 422 `SIMULATION_RESULT_OUT_OF_RANGE` for non-finite results, 500 `INTERNAL_ERROR` with a fixed message, and a bodiless 204 preflight. *Migration:* handle 413, 422 and 500 as well as 400.
- **Package contents (#293).** The manifest has no `prepare` or other install scripts (Git installs need `npm ci && npm run build`; contributors run `npm run hooks:install`). Declaration maps, docs other than USAGE, API_REFERENCE, QUICK_START, `api/` and examples, and the unreachable `browser-native-reference-*` and `schema/{camera,scene}.js` modules are no longer shipped. *Migration:* read the other guides in the repository.

### Added

- **`simulateCapture()` (#300).** A full capture from a few options, returning the image, packed RAW, executed request and plan, provenance and an `assumptions` list naming every default. Exposure modes manual, aperture-priority, shutter-priority and program; white balance by scene illuminant, auto, none, Kelvin/tint or gains; output `srgb-8`, `srgb-16` or `jpeg`. Procedural chart presets (uniform, slanted edge, Siemens star, step wedge, grey ramp, checkerboard, point grid, caller-spectrum patches) with `resolveChartScene` and helpers; `SIMULATE_CAPTURE_FACADE_VERSION` 1.0.0; `docs/QUICK_START.md` (shipped) and `docs/examples/simulate-capture.mjs`.
- **`simulateCapture()` uses the 2.0 features (#306, #307).** All opt-in; without the new options the 1.0 facade output is byte-identical. `output.format: "png"` with `colorEncoding` `srgb`, `display-p3`, `rec2020`, `rec2100-pq` or `rec2100-hlg` (the unclipped linear development is converted through CIE XYZ, clipped once in the target gamut and signalled with cICP; PQ/HLG place RAW white at the BT.2408 reference white) and optional `gamutMapping: "perceptual"` (constant CIELAB L* and hue); `output.format: "dng"`; `output.demosaic` (`bilinear`, `malvar-he-cutler`) and `borderHandling` (`margin`, `mirror`); `lens.projection`, `lens.distortion` (radial or Brown–Conrady), `lens.vignetting` and `lens.psf`; `motion.angularVelocityRadPerSec` and `motion.shutter: "rolling"`. Every choice is listed in `assumptions`.
- **Native RAW DNG (#307).** `serializeNativeRawDng()` writes a lossless 16-bit CFA DNG directly from packed native RAW: per-phase BlackLevel and CFAPattern from the ActiveArea origin, WhiteLevel from the effective saturation code, ActiveArea, DefaultCrop, Orientation, ColorMatrix1, ForwardMatrix1, AsShotNeutral, BaselineExposure and an optional NoiseProfile. It declares no linear master and counts saturation flags DNG cannot carry. `NATIVE_RAW_DNG_SCHEMA_VERSION` 1.0.0.
- **Colorimetry (#291).** Analytic CIE 1931 colour-matching functions (Wyman et al. 2013, labelled approximation) or caller-tabulated CMFs; `integrateSpectrumToXyz`; Planck radiance, illuminant A, CIE daylight with caller-supplied basis spectra, Kim et al. Planckian locus, McCamy CCT and nearest-locus CCT/Duv with its inverse; chromatic adaptation (Bradford, CAT02, CAT16, von Kries-HPE, XYZ scaling, degree of adaptation); CIELAB/LCh and ΔE76, CIE94 and CIEDE2000; `estimateCameraColorMatrix`; RGB colour spaces (sRGB, Rec.709, Display P3, Rec.2020) and sRGB, BT.709, BT.1886, PQ and HLG transfers; gamut mapping. `resolveColorTemperatureWhiteBalance` turns Kelvin + tint into channel gains, and `calculateCaptureColorTransform` takes an optional adaptation `transform`.
- **Sensor (#290).** `createIsoGainReadoutRegimes()` (ISO-dependent analog and digital gain with per-conversion-gain read noise); regime fields `adc.digitalGain`, `adc.integralNonLinearity`, `exposureIndexGain`; opt-in fixed-pattern noise (`parseSensorFixedPatternNoiseProfile`, `calculateSensorFixedPatternSite`, `SENSOR_FIXED_PATTERN_NOISE_MODEL`); a `log-linear-temperature-table` dark-current model; tier `rollingReadoutTiming` and `fixedPatternNoise` assets.
- **RAW development (#295).** `highlightMode` (`clip` or `reconstruct`) with diagnostics; tone curves `extended-reinhard-luminance` and `naka-rushton-luminance`; `calculateEffectiveSaturationCode`; DNG ForwardMatrix1, BaselineExposure, NoiseProfile and AnalogBalance; progress reporting on development and native SDR; `createPhotographicExportPair(input, { signal })`.
- **Optics (#296, #303).** Fisheye and equirectangular projections (`calculateLensProjection*`, optional `projectionModel` on field of view); Brown–Conrady distortion and its inverse; longitudinal chromatic aberration and Cauchy dispersion; natural and mechanical vignetting; polygon-pupil Fraunhofer PSF; Zernike/Seidel wavefronts and Maréchal Strehl ratio; centroid-aligned and rotational PSF interpolation; a linear polarizer (filter schema 0.2.0); atmospheric haze; focus breathing. Geometric mappings gain `brown-conrady` and `projection-remap` transforms (mapping schema 0.2.0), and environment capture accepts an optional `lensFieldMapping`, composed by the production plan.
- **Motion, video and flash (#297).** Electronic rolling-shutter exposure schedules, so skew, partial exposure and flicker banding emerge in image formation; video frame sequences and shutter-angle helpers; flash guide number, pre-flash TTL and high-speed sync (sync schema 0.2.0); the `highlight-priority` metering policy.
- **Export formats (#298).** `parseDngRawImage` (bounded DNG/TIFF-EP reader, uncompressed and lossless JPEG, 8–16 bit) with `DNG_IMPORT_SCHEMA_VERSION` 1.0.0 and `DNG_IMPORT_LIMITS`; `parseLosslessJpeg` (ITU-T T.81 Annex H); `serializePngImage` (8/16-bit RGB PNG with sRGB, iCCP or cICP for Display P3, BT.2020, PQ and HLG, mDCV/cLLI metadata, deterministic in-house zlib); `EXPORT_JPEG_ENCODER_ID`. AVIF and HEIC are not provided.
- **Processing (#302).** Bilinear and Malvar–He–Cutler Bayer demosaic profiles, AHD demosaicing and CFA-plane reconstruction; `borderHandling: "mirror"` for RAW development; noise-optimal HDR bracket merge and BT.2020 PQ/HLG encoding; Reinhard and Durand–Dorsey tone mapping, exposure fusion, focus stacking and known-rotation panoramas; bilateral, non-local-means, unsharp mask and an explicitly synthetic film grain; a shared `ProcessingTask` contract. All opt-in. See `docs/PROCESSING.md`.
- **Opt-in WebGPU backend (#304).** `createImageKernelAccelerator()` runs isoplanatic PSF convolution, native capture SDR and packed RAW development as `webgpu-f32`, labelled with an a-priori float32 error bound and never claimed bit-identical; the CPU float64 reference stays the default. Also `calculateIrradianceConvolution()` and its plan (schema 0.1.0), `ImageKernelExecutionError`, and the repository-only `npm run test:webgpu`. See `docs/WEBGPU.md`.
- **Optical-stage reuse (#288).** `NativeEnvironmentRawInput.opticalStage` returns an opaque optical stage, and `createNativeEnvironmentSensorStageTask()` re-runs only dark charge, capacity, noise and ADC for post-optics edits; optical changes are refused.
- **Smaller additions.** `PrintJpegInput.pixelsPerInch` (1–65535; #278); the `LensComplexPupilPsf.sampling` field (#284); `SENSOR_SPECTRAL_RESPONSE_CHANNEL_BINDING_FORMAT` (#293); a `"default"` export condition so Node ≥ 22.12 can `require()` the package, the `./package.json` export, JS source maps with inline sources, and declarations that type-check with `lib: ["es2022"]` alone (#293).

### Fixed

- Captures, packed RAW and export hashes (`simulationHash`, DNG/JPEG SHA-256) are identical across V8 and JavaScriptCore, and the POC hash corpus passes on every engine without overrides (#293).
- ISO now changes RAW and developed brightness; base-ISO white sits at ADC full scale instead of code 20512 of 65535 (#290).
- ADC round-half-up is exact (0.49999999999999994 rounds to 0), and Poisson draws for means ≥ 1e9 have the correct variance (#290).
- RAW development: double white balance, AsShotNeutral written as the camera white squared, coloured clipped highlights, ignored saturation flags, WhiteLevel written as the ADC maximum, BlackLevel and CFA phase taken from the absolute origin instead of the ActiveArea, and an unclear error when Web Crypto is missing (#295).
- Print and paired-export JPEG Exif carry every Exif 2.32 mandatory tag for compressed images (#278, #298).
- `Math.floor(x + 0.5)` rounding replaced by exact rounding in SDR rendering, linear encoding and Print JPEG sRGB codes (#295, #298).
- Auto-ISO with Shutter or Aperture Priority picks a grid value equal to the ideal within `settingEquals` tolerance, and grid end points within tolerance are no longer reported as clamped (#272, #281).
- Valid exit-pupil declarations are no longer rejected, and packaged docs no longer link to unshipped files (#293).
- The illumination-vignetting interior-extremum solver uses a stable scaled quadratic (#296).
- `resolveLensSampledPsf` no longer rejects an interpolated pupil throughput that floating-point weights lift a few ulps above 1 (#307).
- `simulateCapture()` validates pupil sampling (4–64 angular samples, at most 256 rays) before any work (#306).
- `highlight-weighted` metering is documented as a highlight-emphasis mean (about 0.5–0.8 EV darker than uniform in bright-accent scenes); its behaviour is unchanged, and `highlight-priority` places highlights (#297).

### Performance

Unless marked otherwise, output is bit-identical to the code before it, checked by committed hash and frozen-oracle tests. Timings come from the source PRs on small fixtures on a shared 4-vCPU Linux host under Node 24, so they are indicative only.

- Native environment RAW (#285, #292, #294): one finite-number pre-walk, a cached parse of engine-owned PSF profiles, one PSF parse per event instead of per site, no per-site serialization of shared state, and site plans that keep only the frozen request and image-plane point. Native acquisition is 2.2–3.0× faster on the 2×2 workloads; with a large sampled PSF, CPU per site falls by about 30 % and a site plan by about 25 → 8 MB. The native RAW identity walk is about 3× faster (73 → 46 µs per site).
- Native SDR uses a typed-array kernel (about 10–13× faster, 24 MP 8-bit 33.9 → 3.3 s) and an exact LUT-based 8-bit sRGB quantization (#286, #295).
- RAW development uses a typed kernel: 10–15× faster at 1 MP, 24 MP in 3.8–4.6 s instead of 33–42 s; creation is O(metadata) (220 → 4 ms at 24 MP); 24 MP peak array memory falls from 389 to 229 MiB (#295). The output changes listed under Breaking changes are intentional and separate.
- JPEG: an exact-order faster DCT and entropy coder (about 1.6–2.2×; #286), a growing output buffer instead of a zero-filled full budget (a 384-byte JPEG at a 256 MB budget: 256 MB / ~130 ms → 64 KiB / 0.02 ms), and Print JPEG strip reads with an sRGB LUT (24 MP 1:1: 375,000 → 3,000 provider reads; 4 MP → 0.25 MP: 1,245 → 339 ms) (#298).
- Stabilization evaluation is linear-time (16,000 samples: 3,100 → 222 ms), and native acquisition and development yield to the host about every 8 ms, now also between sites inside a tile so `cancel()` takes effect after about one site (#287, #292).
- Optional optical-stage reuse re-runs the sensor stage 5.0–11.4× faster than a full recompute (#288).
- Native environment RAW (and so `simulateCapture()`) runs sites that match a self-verified template through a lean per-site executor: the same maths in the same floating-point order, without redundant per-site re-validation and result envelopes; every data-dependent check remains and falls back to the full engine functions, so RAW, callbacks and errors are byte-identical. `simulateCapture()` 64×64 6.0 → 0.87 s CPU and 128×128 20.6 → 2.2 s; RAW stage 0.95 → 0.12 ms per site. Sampled-PSF and lens-mapped sites keep the full path (#305).
- No GPU speedup is claimed for the WebGPU backend; on the software adapter it was slower than the CPU (#304).
